# API ордеров

Программный интерфейс для создания ордеров, получения реквизитов и отслеживания статуса оплаты.

## Авторизация

Каждый запрос к API должен содержать заголовок `Api-Key` со значением API-токена.

Токен создаётся в личном кабинете в разделе «Профиль», блок «API-токены»:

1. Укажите имя токена (уникальное среди ваших токенов) и нажмите «Создать».
2. Скопируйте значение токена. Оно показывается только один раз, после закрытия окна посмотреть его снова нельзя.
3. Подставляйте токен в заголовок `Api-Key` каждого запроса.

Одновременно можно иметь не больше 10 токенов. Ненужный или скомпрометированный токен удалите: запросы с ним сразу перестанут проходить.

Если заголовок не передан или токен не найден, API отвечает `401 Unauthorized` без тела.

```
Api-Key: <ваш токен>
```

## Ошибки

Ошибки возвращаются в формате JSON. Причина ошибки указана в поле `description`:

```json
{
  "instance": "/api/v1/order",
  "status": 400,
  "title": "Bad Request",
  "type": "/docs/errors/bad-request",
  "timestamp": 1761206400000,
  "description": "Поле «amount» должно быть больше нуля."
}
```

| Поле | Описание |
|---|---|
| `instance` | Путь запроса. |
| `status` | HTTP-статус ответа. |
| `title` | Название HTTP-статуса. |
| `type` | Тип ошибки. Есть не во всех ответах. |
| `timestamp` | Время ошибки, миллисекунды Unix-времени. Сообщите его поддержке, если обращаетесь по ошибке. |
| `description` | Причина ошибки. |

В шаблонах сообщений ниже `<поле>`, `<значение>` и подобные подставляются из запроса.

Ошибки, общие для всех методов:

| HTTP-статус | Ситуация | Сообщение |
|---|---|---|
| `401 Unauthorized` | Заголовок `Api-Key` не передан или токен не найден. | Тела нет. |
| `500 Internal Server Error` | Внутренняя ошибка. | `Обратитесь в поддержку.` |

## Создание ордера

`POST /api/v1/order`

Тело запроса передаётся в формате JSON:

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `internalId` | строка | да | Идентификатор ордера в вашей системе, уникальный: ордер с таким `internalId` не должен уже существовать. |
| `amount` | целое число | да | Запрашиваемая сумма ордера в рублях, больше нуля. |
| `methods` | массив | да | Методы оплаты, хотя бы один: `CARD` (карта), `SBP` (СБП). |
| `callbackUrl` | строка | нет | Адрес для [КБ](#колбэки) об изменении статуса ордера, только `https`. Если не указан, используется адрес из профиля. |
| `userId` | строка | нет | Идентификатор вашего пользователя, который будет совершать оплату. Передавать необязательно, но в некоторых случаях он увеличивает шанс получения реквизитов и ускоряет их получение. |

Заголовки:

| Заголовок | По умолчанию | Описание |
|---|---|---|
| `Content-Type` | — | Обязательный, `application/json`. |
| `Search-Timeout-Seconds` | `30` | Сколько секунд ждать поиска реквизитов, от 5 до 300. |
| `Async-Request` | `false` | Допустимые значения `true` и `false`. `true` — не ждать поиска реквизитов, итоговый статус придёт в КБ. |
| `Test-Order` | `false` | Допустимые значения `true` и `false`. `true` — создать тестовый ордер. Реквизиты в нём ненастоящие, оплачивать по ним нельзя. |

> [!TIP]
> При синхронном создании ответ приходит только после окончания поиска реквизитов. Указывайте `Search-Timeout-Seconds` на 1–2 секунды меньше таймаута HTTP-запроса на вашей стороне, чтобы получить ответ до того, как ваш клиент оборвёт соединение.

Пример запроса:

```json
{
  "internalId": "order-1001",
  "amount": 5000,
  "methods": ["CARD", "SBP"],
  "callbackUrl": "https://example.com/callback",
  "userId": "user-42"
}
```

Ответ:

- `201 Created` при синхронном создании: ордер возвращается с итоговым результатом поиска. Обычно это статус «Новый» с реквизитами или «Реквизиты не найдены». Если ордер отменили во время поиска, он вернётся в статусе «Отменен» без реквизитов. Отменить ордер во время поиска может как сам клиент через API, так и сотрудник поддержки.
- `202 Accepted` при асинхронном создании (`Async-Request: true`): ордер возвращается в статусе «Поиск реквизитов». Итоговый статус придёт в КБ, если адрес КБ указан в запросе или в профиле. Если адреса нет, узнавайте статус, запрашивая ордер.

```json
{
  "id": "6f1c2b9e-3d4a-4b8e-9a2f-1e7d5c3b2a10",
  "createdAt": 1761206400000,
  "internalId": "order-1001",
  "status": "NEW",
  "amount": 5003,
  "method": "CARD",
  "details": "2200 0000 0000 0000",
  "bank": "Банк",
  "callbackUrl": "https://example.com/callback"
}
```

> [!WARNING]
> **Сумму для оплаты берите из поля `amount` ответа, а не из своего запроса.** После получения реквизитов сумма может отличаться от запрошенной. Оплата ожидается ровно на сумму из ответа: пользователь должен перевести именно её.

| Поле | Описание |
|---|---|
| `id` | Идентификатор ордера в процессинге. |
| `createdAt` | Время создания, миллисекунды Unix-времени. |
| `internalId` | Идентификатор ордера в вашей системе. |
| `status` | Статус ордера. |
| `amount` | Сумма в рублях, которую нужно оплатить. |
| `method` | Метод оплаты, по которому найдены реквизиты. |
| `details` | Реквизиты для оплаты. |
| `bank` | Банк реквизитов. |
| `callbackUrl` | Адрес, на который отправляются КБ. `null`, если адрес не указан ни в запросе, ни в профиле. |

Поля `method`, `details` и `bank` равны `null`, пока реквизиты не получены: в статусах «Поиск реквизитов» и «Реквизиты не найдены», а также если ордер отменили во время поиска.

Ошибки:

| HTTP-статус | Ситуация | Сообщение |
|---|---|---|
| `400 Bad Request` | Обязательное поле не передано или значение поля не прошло проверку. | `Поле «<поле>» должно быть заполнено.`<br>`Поле «amount» должно быть больше нуля.`<br>`Поле «methods» должно содержать хотя бы одно значение.`<br>`Поле «callbackUrl» должно быть корректным адресом с протоколом https.` |
| `400 Bad Request` | В `methods` неизвестный метод или у поля неверный тип, например строка в `amount`. | `Поле «<поле>» содержит некорректное значение «<значение>».` |
| `400 Bad Request` | Тело запроса не передано или не является корректным JSON. | `Тело запроса не передано.`<br>`Тело запроса содержит некорректные данные.` |
| `400 Bad Request` | Ордер с таким `internalId` уже существует. | `Внутренний идентификатор (internalId) должен быть уникальным, ордер с таким идентификатором уже присутствует в системе.` |
| `400 Bad Request` | Некорректное значение заголовка: `Search-Timeout-Seconds` вне диапазона 5–300 или не число, `Async-Request` или `Test-Order` не `true`/`false`. | `Таймаут поиска реквизитов не может быть меньше 5 секунд.`<br>`Таймаут поиска реквизитов не может превышать 300 секунд.`<br>`Параметр «<заголовок>» содержит некорректное значение «<значение>».` |
| `415 Unsupported Media Type` | Заголовок `Content-Type` не `application/json`. | `Тип содержимого «<тип>» не поддерживается.` |
| `503 Service Unavailable` | Сервис перегружен, ордер не создан. Повторите запрос позже. | `Обратитесь в поддержку.` |

Если ошибок проверки полей несколько, сообщения перечисляются в `description` через пробел, например `Поле «amount» должно быть больше нуля. Поле «methods» должно содержать хотя бы одно значение.`

## Получение ордера

`GET /api/v1/order/{id}`

Возвращает ордер в том же формате, что и при создании.

Пример запроса: `GET /api/v1/order/6f1c2b9e-3d4a-4b8e-9a2f-1e7d5c3b2a10`

Пример ответа `200 OK`:

```json
{
  "id": "6f1c2b9e-3d4a-4b8e-9a2f-1e7d5c3b2a10",
  "createdAt": 1761206400000,
  "internalId": "order-1001",
  "status": "SUCCESS",
  "amount": 5003,
  "method": "CARD",
  "details": "2200 0000 0000 0000",
  "bank": "Банк",
  "callbackUrl": "https://example.com/callback"
}
```

Ошибки:

| HTTP-статус | Ситуация | Сообщение |
|---|---|---|
| `400 Bad Request` | Ордер не найден. | `Ордер не найден.` |
| `400 Bad Request` | `id` не является UUID. | `Параметр «id» содержит некорректное значение «<значение>».` |

## Отмена ордера

`PATCH /api/v1/order/{id}`

Переводит ордер в статус «Отменен». При успешной отмене ответ `200 OK` без тела.

Ошибки:

| HTTP-статус | Ситуация | Сообщение |
|---|---|---|
| `400 Bad Request` | Ордер не найден. | `Ордер не найден.` |
| `400 Bad Request` | Ордер уже отменён. | `Ордер уже в статусе «Отменен».` |
| `400 Bad Request` | Ордер в статусе «Реквизиты не найдены» или «Просрочен». | `Переход ордера из статуса «<статус>» в статус «Отменен» не выполняется.` |
| `400 Bad Request` | Ордер в статусе «Успешный». | `Переход ордера из статуса «Успешный» в статус «Отменен» запрещён.` |
| `400 Bad Request` | `id` не является UUID. | `Параметр «id» содержит некорректное значение «<значение>».` |

Пример тела ответа:

```json
{
  "instance": "/api/v1/order/6f1c2b9e-3d4a-4b8e-9a2f-1e7d5c3b2a10",
  "status": 400,
  "title": "Bad Request",
  "type": "/docs/errors/bad-request",
  "timestamp": 1761206400000,
  "description": "Ордер уже в статусе «Отменен»."
}
```

## Список ордеров

`GET /api/v1/order`

Параметры запроса:

| Параметр | Описание |
|---|---|
| `status` | Фильтр по статусу ордера. |
| `method` | Фильтр по методу оплаты: `CARD` или `SBP`. |
| `page` | Номер страницы, с нуля. |
| `size` | Размер страницы, по умолчанию 20. |
| `sort` | Сортировка в формате `<поле>,<направление>`, например `createdAt,desc`. Поле — одно из полей ордера: `id`, `createdAt`, `internalId`, `status`, `amount`, `method`, `details`, `bank`, `callbackUrl`. Направление — `asc` (по возрастанию, по умолчанию) или `desc` (по убыванию). Чтобы сортировать по нескольким полям, передайте параметр несколько раз. Без `sort` порядок ордеров не гарантируется. |

Пример запроса: `GET /api/v1/order?status=NEW&page=0&size=2&sort=createdAt,desc`

Пример ответа:

```json
{
  "content": [
    {
      "id": "6f1c2b9e-3d4a-4b8e-9a2f-1e7d5c3b2a10",
      "createdAt": 1761206400000,
      "internalId": "order-1001",
      "status": "NEW",
      "amount": 5003,
      "method": "CARD",
      "details": "2200 0000 0000 0000",
      "bank": "Банк",
      "callbackUrl": "https://example.com/callback"
    },
    {
      "id": "0b8d4e2a-7c1f-4a3e-8d6b-5f9a2c1e3b47",
      "createdAt": 1761206100000,
      "internalId": "order-1000",
      "status": "NEW",
      "amount": 1500,
      "method": "SBP",
      "details": "+7 900 000-00-00",
      "bank": "Банк",
      "callbackUrl": "https://example.com/callback"
    }
  ],
  "page": {
    "size": 2,
    "number": 0,
    "totalElements": 7,
    "totalPages": 4
  }
}
```

Ошибки:

| HTTP-статус | Ситуация | Сообщение |
|---|---|---|
| `400 Bad Request` | Неизвестное значение `status` или `method`. | `Поле «<параметр>» содержит некорректное значение «<значение>».` |
| `400 Bad Request` | В `sort` указано поле, которого нет в списке. | `Сортировка по полю «<поле>» не поддерживается.` |

## Колбэки

КБ (колбэк) — уведомление об изменении статуса ордера, которое процессинг отправляет на ваш сервер.

**Куда.** На `callbackUrl` ордера: адрес из запроса на создание, а если он не указан, адрес из профиля. Если адреса нет ни там, ни там, КБ не отправляются.

**Когда.** При каждом изменении статуса ордера, в том числе при отмене через API. При синхронном создании КБ о результате поиска реквизитов не отправляется: этот результат приходит в ответе на запрос создания.

**Формат.** `POST` с заголовком `Content-Type: application/json`. Тело совпадает с ответом на [получение ордера](#получение-ордера):

```json
{
  "id": "6f1c2b9e-3d4a-4b8e-9a2f-1e7d5c3b2a10",
  "createdAt": 1761206400000,
  "internalId": "order-1001",
  "status": "SUCCESS",
  "amount": 5003,
  "method": "CARD",
  "details": "2200 0000 0000 0000",
  "bank": "Банк",
  "callbackUrl": "https://example.com/callback"
}
```

**Ответ вашего сервера.** Если ваш сервер не ответит кодом `2xx` в течение 3 секунд, запрос считается неудачным, и КБ будет отправлен повторно: ещё до трёх раз, через 10, 30 и 90 секунд. Поэтому отвечайте статусом `200` сразу после получения запроса, а обработку КБ выполняйте параллельно. Тело ответа не нужно. Если все попытки неудачны, КБ больше не отправляется, и актуальный статус можно узнать, запросив ордер. Если статус ордера с тех пор не менялся, поддержка может отправить последний недоставленный КБ повторно, поэтому один и тот же КБ может прийти ещё раз.

**Порядок.** КБ по одному ордеру приходят строго в том порядке, в котором менялся статус. Следующий КБ отправляется только после того, как предыдущий доставлен или исчерпал все попытки. Каждый КБ содержит состояние ордера на момент смены статуса. КБ по разным ордерам отправляются независимо друг от друга.

## Константы

### Статусы ордера

| Статус | Название | Смысл |
|---|---|---|
| `SEARCHING` | Поиск реквизитов | Ордер создан, идёт поиск реквизитов. |
| `DETAILS_NOT_FOUND` | Реквизиты не найдены | Реквизиты не найдены. Конечный статус. |
| `NEW` | Новый | Реквизиты найдены, ожидается оплата. |
| `SUCCESS` | Успешный | Оплата подтверждена. Конечный статус. |
| `CANCELED` | Отменен | Ордер отменен. Не конечный статус: если оплата по ордеру всё же поступит, он перейдёт в «Успешный», также по нему может быть открыт спор. |
| `TIMEOUT` | Просрочен | Истекло время жизни ордера. Не конечный статус: если оплата по ордеру всё же поступит, он перейдёт в «Успешный», также по нему может быть открыт спор. |
| `DISPUTE` | В споре | По ордеру открыт спор. По итогам спора ордер переходит в «Успешный» или «Отменен». |

### Методы оплаты

| Метод | Название |
|---|---|
| `CARD` | Карта |
| `SBP` | СБП |
